# Установка для разработки

Для разработки предусмотрены два контура. Они дополняют друг друга и не обязаны работать одновременно.

## Вариант 1: Docker Compose

Используйте, если меняете CMS API, frontend, модель данных или авторизацию и вам не нужна реальная Kubernetes-топология.

Преимущества:

- быстрый цикл изменения кода;
- простая отладка процессов;
- меньше требований к памяти и CPU.

[Перейти к инструкции](docker-compose.md)

## Вариант 2: kind

Используйте для полного сценария: CMS → Clabgate → Clabernetes → JupyterLab/terminal/checker/capture.

Преимущества:

- поведение близко к production Kubernetes;
- можно проверять ingress, namespace попытки и ServiceAccount;
- запускается настоящая лабораторная работа.

[Перейти к инструкции](kind.md)

> **Нужна иллюстрация:** два параллельных dev-контура. Слева Docker Compose с frontend/backend/database, справа kind с полным набором компонентов и namespace лаборатории.
