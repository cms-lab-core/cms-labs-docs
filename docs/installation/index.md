# Выбор варианта установки

CMS Labs можно запускать по-разному в зависимости от задачи.

| Вариант | Для чего подходит | Состояние данных | Оркестрация |
| --- | --- | --- | --- |
| Docker Compose | быстрая разработка backend/frontend | локальные volumes | Docker |
| kind | разработка полного контура, Clabgate и лабораторий | локальный kind-кластер | Kubernetes в Docker |
| VM + cloud-init | демонстрация, пилот, выделенный учебный сервер | диски виртуальной машины | Kubernetes на одной VM |
| Kubernetes + Helm | production и многопользовательская работа | внешние или кластерные хранилища | существующий кластер |

## Рекомендуемый путь

1. Для изменения CMS начните с [Docker Compose](development/docker-compose.md).
2. Для Clabgate, терминалов, JupyterLab и топологий используйте [kind](development/kind.md).
3. Для пробного удалённого стенда подготовьте [VM через cloud-init](virtual-machine.md).
4. Для эксплуатации используйте [Helm в Kubernetes](kubernetes.md).

> **Нужна иллюстрация:** диаграмма выбора варианта установки в виде дерева решений: «что разрабатываем?» → CMS / Kubernetes-интеграцию / демонстрационный сервер / production.

## Общие требования

- Linux amd64 или arm64;
- доступ к OCI-образам и Helm-чартам в GHCR;
- DNS и TLS для внешнего доступа;
- GitHub/GitLab или другой Git-сервер для репозиториев лабораторных;
- ресурсы, достаточные для сетевых образов выбранного курса.

Точные поддерживаемые версии Kubernetes, Helm, Containerlab и Clabernetes будут зафиксированы перед первым стабильным релизом документации.
