# Подготовить и подключить лабораторную

## Начать с рабочего примера

Возьмите за основу [cms-labs-simple-task](https://github.com/cms-lab-core/cms-labs-simple-task) и запустите его в [локальном kind](../usage/kind.md). Заменяйте компоненты по очереди, чтобы можно было проверить, на каком шаге возникла ошибка.

1. **Топология.** Подготовьте одну `Topology`. Укажите образы, имена узлов, интерфейсы и линки. Используйте версии образов, доступные узлам кластера.
2. **Задание.** Положите notebook и необходимые файлы в Git. Включите в notebook инструкции, таблицы и поля для отчёта, которые пригодятся без отдельной методички. Проверьте все пути из чистого клона.
3. **Терминалы и захват.** Укажите команды для типов узлов и лимиты захвата, если работа использует эту возможность. Контроллеры устанавливаются в кластере, а файлы задания описывают, на каких узлах доступен каждый сервис.
4. **Проверки.** Выберите набор, доступный в образе checker этого кластера. В рабочем примере он задаётся ключом `sdn_lab_5`. Проверка должна возвращать условие, статус и сообщение, по которому можно найти ошибку.
5. **Ревизия.** Зафиксируйте проверенную ветку, тег или SHA по формату `https://git.example.org/course/lab.git#main`. Дайте Clabgate доступ на чтение приватного репозитория, если он закрыт.

Подробности рабочих файлов, подстановок и допустимых объектов описаны в [контракте лабораторной](../technical/lab-contract.md).

## Подключить к CMS

1. Зарегистрируйте сервер **K8S** и проверьте связность с Clabgate.
2. В [«Маршрутах LTI»](../admin/routes.md) создайте маршрут. Укажите имя, Git URL в поле **«Подключение к лабораторной работе»**, ключ checker в поле **«Запуск тестов лабораторной работы»** и явно выберите сервер K8S.
3. Для запуска из Moodle добавьте уникальную пару `ключ=значение` в элемент курса и в **«Query LTI для элемента курса»**. Проверьте, что [регистрация LTI](../admin/integrations.md) настроена.
4. Для самостоятельного запуска включите каталог через `LAB_CATALOG_ENABLED=true` и откройте карточку работы под тестовым пользователем.

## Принять работу перед выдачей студентам

| Что проверить | Как выглядит исправный результат |
| --- | --- |
| Первый запуск | Создан один namespace попытки. Узлы и JupyterLab готовы, в обзоре видна ожидаемая ревизия Git. |
| Материалы | Notebook открывается, ссылки на артефакты работают, текст соответствует топологии и проверкам. |
| Терминалы и PCAP | Доступны терминалы нужных узлов. Захват можно скачать, если он предусмотрен заданием. |
| Checker | С пустой конфигурацией видны понятные причины отказа. Эталонная конфигурация проходит обязательные проверки. |
| Moodle | Результат сохраняется в CMS, а при настроенном AGS появляется в журнале курса. |
| Завершение | После экспорта отчёта сессия завершается, Kubernetes освобождает ресурсы. |
